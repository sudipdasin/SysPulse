# SysPulse candidate catalogue v1

Publication Manager 4.0 discovers this file from an immutable commit of `release-candidates`. This is repository-controlled release evidence, not an owner signature. Do not register a candidate until its native regression tests, exact signed prior-DEB upgrade, tamper rejection, package identity, installed runtime and deployed build/install reports pass. Record the SHA-256 from the verified build logs, not merely from the mutable artifact server. The `tested_from` and `tested_from_sha256` fields must describe the exact currently published signed package. Never reuse a version with a different digest. Retain evidence and only add validated entries; do not register untested candidates. Candidate origin must match the version-specific SysPulse Render HTTPS naming contract. The GUI verifies the actual downloaded DEB and existing trust anchor, and requires separate owner signing and publication approvals. Neither this catalogue nor its update publishes the signed update feed. No CI workflows, scripts or executable code belong on this branch. Use source commits with [skip ci]; no GitHub Actions or CircleCI. Revalidate new release builds from the actual current signed feed after owner publication. Future incompatible package naming/schema requires a reviewed manager update.
