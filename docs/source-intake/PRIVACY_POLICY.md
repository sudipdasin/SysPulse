# Source intake privacy policy

Inspect attachments privately as untrusted data; never execute them. Deduplicate using a private inventory. Import only newly written or reviewed portable source. Exclude raw diagnostics, real configuration, personal names, user/home paths, device serials, hostnames, hardware identifiers, tokens, credentials, private network details, game records and identifying metadata. Keep identifiers out of filenames, comments, commit messages, reports and archive metadata as well as code. Use synthetic fixtures. Scan all outbound content, manually review uncertain matches, and fail closed on inaccessible or unreviewed inputs. Runtime exports remain local and detailed export is opt-in. Do not publish sensitive source fingerprints. Never upload unreviewed archives or executables. Use native authorization instead of retaining passwords. A pattern scan is not a guarantee of anonymity. Preserve required copyright and license notices; repository account ownership is public metadata, distinct from private machine data.
