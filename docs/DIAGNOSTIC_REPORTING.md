# Diagnostic reporting deployment contract

Client: Settings & help and Reports → Review diagnostic sharing. Off by default; each level change invalidates preview and consent. Minimum aggregates counts; medium adds fixed catalog outcomes; maximum adds native launcher/cleaner preflight and imported audit outcomes. Import accepts v2.0.0 audit reference alpha.19 only and records coarse allowlisted installed release separately. No free text, raw output, machine fingerprint, identifiers or paths from user data. Fixed probe names may describe standard system paths, not user paths. Native preflight never runs commands; execution outcomes are existing session records or user-imported evidence, not certification. Local analysis is automatic and advisory. No automatic mutation.

Relay: tools/reporting/relay.py validates schema independently, rejects unknown fields/IDs, enforces size and level, rate limits and deduplicates identical normalized reports for one hour, and writes only validated JSON plus deterministic triage to the fixed canonical repository issues endpoint via server-only credential. Treat issues as untrusted evidence. The report is public if repository issues are public. No client ID or automatic retry; HTTPS proxy and hosting provider may observe connection metadata. Before activation: provision narrowly scoped issues-write service credential (not a personal token in app), approve public visibility/retention, configure HTTPS reverse proxy with strict body/connection limits and access log minimization, verify end-to-end with synthetic report, set compile-time SYSPULSE_REPORT_ENDPOINT. Default empty endpoint disables send; no credentials stored in source. Global in-memory caps reset on service restart; production abuse controls and monitoring remain required. No paid service or live relay deployment in this checkpoint. No code or system changes directly driven by reports.
