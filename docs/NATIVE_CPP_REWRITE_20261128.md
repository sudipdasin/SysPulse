## Architecture
- C++17 standard-library core; typed capabilities, platform-independent data models, read-only collectors, bounded parsing, risk and permissions, task cancellation/deadlines, local audit, explicit plan/preview/execute/verify and rollback. Reuse existing tested C++ functions where possible. No embedded Python, shell, web UI, Electron or Qt runtime in the final native product.
- Native OS backends: Linux /proc, /sys, netlink, appropriate systemd/PolicyKit and distro package APIs; Windows Win32, SCM, native process/memory/storage/network APIs and UAC. Use typed direct process invocation only when an external OS utility is the supported interface (e.g. distribution package manager); no shell interpolation. No platform-independent claim for unsupported features. Linux Mint 22.x XFCE X11 amd64 first; Windows 10/11 x64 second; Wayland, other Linux distros and macOS require independent adapters and tests. Native OS SDK/libraries are allowed; cross-platform system administration cannot be accomplished using the C++ standard library alone.
- Native UI design: retain Precision visual system, full navigation, global search, responsive Overview, Observatory, Forge, all approved workspaces, accessible focus/keyboard, DPI scaling and localization. Direct X11/Win32 implementations evaluated with actual native tests; Wayland requires compositor-aware protocol support and is not equivalent to X11. Do not revive rejected historical X11 previews as replacement. Keep approved Qt build available until UI and feature parity gates pass.
- Privileged helpers in C++ with scoped structured protocol, OS authorization, allowlists, explicit confirmation, secure defaults, no password storage, no automatic mutation at startup. Replace Python/Bash application logic incrementally; packaging/build tools can still use platform tooling without being runtime wrappers.
