# SysPulse development instructions

This repository is the canonical community project. Read docs/PROJECT_HANDOFF.md and docs/source-intake/REPORT.md plus manifest and queue at the beginning of every development cycle. Consume accepted utility IDs, avoid duplication, implement in small isolated branches, test locally, update the queue and report with exact evidence, and merge only validated changes. Never trigger GitHub Actions or CircleCI, even indirectly; verify triggers before ref writes. No paid services or stable release without owner approval. Protect existing features. Prefer native C++/Qt with bounded resources, argument-array subprocesses, least privilege, preview and reversible changes. Never execute incoming raw scripts; inspect privately, sanitize and review all outgoing material before any remote write. No original personal source, logs, configs, real paths, serials, credentials, private metadata or unreviewed binary archives. Never weaken safeguards to finish a task. Report actual blockers, not invented success. No automatic telemetry. Keep future Pro separate; obey GPL and third-party terms.

## Mandatory correction — established application continuity
The owner approved the native Qt Precision white/crimson UI, Observatory monitoring and Forge management. The established implementation is SysPulse 3.0.0-alpha.2 in the legacy tux-steward repository (verified source checkpoint 0105b57667f79129765c56e3f1654cd91c42cf3a). The canonical destination is this repository. Do not develop, extend, release, or substitute the separate X11 0.x previews as the product. Preserve them in history; do not delete work or force-push. Restore the mature Qt source in an isolated migration branch, preserve original UI, features, tests, license and attribution, exclude private files and CI configs, and compare exact source blobs before integration. Do not merge until the full build, inherited tests, desktop regression and installation gates have passed. Extend existing Qt tool catalog, workspace pages, health and authorization mechanisms, not a second application. Target Linux Mint 22.3 XFCE x86_64. Read docs/CONTINUITY.md before all development. GitHub Actions and CircleCI remain prohibited.

## Mandatory release deliverable — XFCE DEB and repository-backed updates
Every distributable SysPulse release must provide a real, complete amd64 .deb for Linux Mint 22.3 XFCE, built from the established Qt application and validated on its target. A source archive, shell installer, bootstrap-only package or obsolete X11 preview does not satisfy this requirement. Provide a direct verified DEB asset link with every release, including previews, and state version, target, source commit, checksum and test evidence. If blocked, explicitly report no verified DEB; never manufacture a placeholder or imply that a source installer is a DEB. See docs/DEB_UPDATE_RELEASE_POLICY.md for required repository-backed updates and release gates. Never invoke GitHub Actions or CircleCI.
